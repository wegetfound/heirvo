# Heirvo Recovery Engine Audit — 2026-06-13

Three parallel deep-dives: engine.rs, scsi_windows.rs, session/output/UI layer.
Field symptom under investigation: mildly-damaged discs ending at ~1% recovered and marked
"complete"; cheap USB-SATA bridges and slim USB drives dropping under load.

## THE FAILURE PIPELINE (why mild discs end at 1%)

A mildly scratched disc in a flaky drive dies in five compounding stages:

1. **Sense misclassification poisons the map** (scsi_windows.rs:736-749).
   `sense_to_error` has NO case for UNIT ATTENTION (key 0x06) or ABORTED COMMAND (0x0B) —
   both fall to `Other` → sector marked failed. NOT READY (0x02, drive spinning up after
   reconnect) → `HardwareError` → failed. After EVERY bridge drop, the first reads hit
   UNIT ATTENTION / NOT READY and are recorded as permanent media damage. ASC/ASCQ never read.

2. **The engine provokes the drops it then mishandles** (scsi_windows.rs:1161-1189, 573).
   `fast_sector_fallback` uses a 1–2s SPTI TimeOutValue; when it expires, storport resets the
   bridge — cheap bridges fall off the bus. The watchdog (`CancelIoEx` at 30s ceiling) has the
   same effect on marginal sectors that need >30s. The fallback path designed to pinpoint bad
   sectors is itself a drop trigger.

3. **Triage interprets a struggling drive as a destroyed disc** (engine.rs:574-576, 809-824).
   `SLOW_FAILS_TO_ESCAPE = 2` with zero retries: two ≥4s failures (a recovering drive does this
   constantly) → leap. `consec_slow_fails` keeps growing across leaps; each landing read on a
   still-recovering drive is another slow fail → next leap. remaining/4 cap COMPOUNDS:
   (¾)ⁿ — ~8-10 consecutive slow fails skips >90% of the disc into Unknown. Skip-ahead has the
   same shape (`FAIL_STREAK_TO_SKIP = 2`, skipped blocks count toward the streak).

4. **Quick mode can't drain the backlog** (engine.rs:475, 500-503, 1199-1201; passes.rs:146).
   SlowRead — the ONLY retry pass in Quick mode — reads 1 sector per I/O with 100ms delay
   (~10 sectors/s = ~18k sectors max in its 30-min cap = ~0.7% of a DVD), and processes
   Failed+Unknown interleaved in LBA order, so genuinely-bad sectors near the front (2 × 12s
   timeouts each) burn the whole budget before reaching the healthy leapt-over swaths.

5. **Plan exhaustion = "Completed"** (engine.rs:385-391; commands/recovery.rs:182-206).
   `run()` returns Completed unconditionally — no check of Unknown count. Session marked
   Completed, promoted to library, UI celebrates. "1% recovered, recovery complete."

Plus the resume killer: **fingerprint instability** (commands/drive.rs:152-162;
session/manager.rs:72-77). Unreadable sector 16 → EMPTY fingerprint → resume never matches →
every insert starts a brand-new session from scratch (hours of progress silently abandoned),
AND all unreadable discs share `Documents\Heirvo\(unreadable)\unreadable.iso` — two different
discs comingle in one ISO (the data-safety bug, worse than the label-collision variant).
Fingerprint also hashes `reader.capacity()` which is unstable on cheap bridges → same disc,
different fingerprint, fresh session.

## RECOMMENDED FIX ORDER (highest leverage first)

**Phase 1 — Stop poisoning the map (small diffs, biggest wins):**
1. Fix sense_to_error: add UNIT ATTENTION + ABORTED COMMAND → retry; NOT READY/becoming-ready →
   TEST UNIT READY poll then retry; only sense key 0x03 → MediumError. Parse descriptor-format
   sense. (C1)
2. Branch on r.error in engine: Timeout/HardwareError → leave Unknown in Triage; only
   slow-mode-retried MediumError converts to Failed. (C4-adjacent)
3. Retry-pass leaps mark Unknown (or Skipped), never Failed; de-escalate leaps in all passes. (H1)

**Phase 2 — Stop provoking drops + survive them:**
4. Raise fallback timeout to ≥6s; map disconnects to DeviceGone in both fallbacks. (H2, H4)
5. TEST UNIT READY ready-wait after reopen, before reapplying mode settings. (H3)
6. Wire DeviceGone through CdSectorReader + implement reset(). (C2)
7. READ CAPACITY: ready-wait + 3-5 retries + TOC lead-out fallback + PVD fallback. (C3)

**Phase 3 — Actually recover the disc:**
8. SlowRead: process Unknown runs FIRST with block reads (they're statistically healthy,
   Triage just leapt over them); Failed singles with remaining budget. Or: re-Triage Unknowns
   until convergence (ddrescue's copy→trim→scrape). (C5)
9. Raise SLOW_FAILS_TO_ESCAPE to 4-6 + cooldown-and-probe before escalating leaps; cap
   cumulative skipped fraction per pass. (C4)
10. Completed → CompletedPartial when unknown+failed > threshold; gate library promotion;
    UI says "X% never attempted — run Overnight". (C6)

**Phase 4 — Data safety:**
11. Composite fingerprint (hash first N readable sectors, not just sector 16; capacity OUT
    of the hash; random per-session fingerprint as last resort). (C7)
12. sync_data() on image BEFORE map checkpoint. (H6)
13. Surface image write errors; pause on destination-full. (H5)
14. change_output_dir moves/copies the existing ISO. (H7)

**Phase 5 — UI truth:**
15. Reset per-session state on URL session switch; session-scope the poll merge. (H9)
16. Distinct error/cancelled phases. (M3)
